# Local DEB build

Requirements: Linux, a full JDK 17 including `jlink` and `jpackage`, `dpkg-deb`,
and `fakeroot`.
On Debian/Ubuntu, the packaging tools are provided by `dpkg-dev` and `fakeroot`.
Internet access is needed for the first Gradle and dependency download.

From the project root:

```sh
./gradlew buildRelease
```

Packaging automatically selects a full JDK 17 using Gradle toolchains, matching
the compiler toolchain. `JAVA_HOME` does not need to point to JDK 17 for packaging;
the Java used to start Gradle can be different. The selected JDK must provide
`javac`, `jlink`, and `jpackage`.

`gradle/gradle-daemon-jvm.properties` also selects JDK 17 for the Gradle daemon,
avoiding the deprecation warning caused by running Gradle itself on Java 15.
The wrapper can still be launched with your existing `JAVA_HOME`.

If JDK 17 is installed outside Gradle's standard discovery locations, add
`org.gradle.java.installations.paths=/path/to/jdk-17` to your
`~/.gradle/gradle.properties`.

The Gradle task compiles the application, creates a DEB with a bundled Java
runtime using Compose Desktop's `packageDeb`, and copies it to:

```text
build/release/[name]-[version]-[architecture].deb
```

For version `1.0.1` on amd64:

```text
build/release/Application-Manager-1.0.1-amd64.deb
```

Change `VERSION` to set the version. The architecture is taken from the DEB
filename generated by `jpackage`; this is a native build for the local machine.
The task builds locally without installing or publishing the package.

DEB packaging also installs the GNOME desktop entry, the transparent stock icon,
and AppStream metadata into standard `/usr/share` locations. The desktop entry's
`StartupWMClass` matches the application's window class. The installer is named
`Application-Manager`, the GNOME menu uses `Application Manager`, and Debian's
internal package identifier is `application-manager`.
